# Domain docs

This repository uses a single context:
- CONTEXT.md: domain glossary.
- docs/adr/: architectural decisions.

Before exploring the codebase, read CONTEXT.md and ADRs relevant
to the work. If these files are absent, proceed silently;
domain-modeling creates them when terms or decisions crystallise.

Use the glossary's vocabulary in issues, proposals, and code.
For missing concepts, reconsider the terminology or note the gap
for domain-modeling.

Surface contradictions with existing ADRs explicitly, identifying
the decision and explaining why it may need reconsideration.
